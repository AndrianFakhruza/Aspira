PRODUCT REQUIREMENTS DOCUMENT
ASPIRA
Platform Form Builder, Survei & Analisis Respons
Versi 2.0 — Rencana Perombakan (Revamp)
September 2026
Disusun berdasarkan audit terhadap kode sumber aplikasi Aspira saat ini
1. Ringkasan Eksekutif
Aspira adalah aplikasi internal berbasis web untuk membuat formulir/survei (form builder), mengumpulkan respons publik, dan menganalisis hasilnya secara visual (chart) melalui panel admin. Aplikasi saat ini dibangun dengan PHP native (tanpa framework) di sisi backend, MySQL (mysqli) sebagai database, serta HTML/JavaScript murni dengan Tailwind CSS (via CDN) di sisi frontend. Fitur inti yang sudah berjalan meliputi: login admin, form builder drag-and-drop sederhana, halaman publik pengisian formulir, dashboard rekap, laporan analisis berbasis chart, manajemen multi-admin, ekspor data ke Excel, serta notifikasi email otomatis (ke responden dan admin) menggunakan PHPMailer.
Dokumen ini merangkum kondisi aplikasi saat ini (as-is), temuan dari audit kode (arsitektur, keamanan, dan pengalaman pengguna), serta rencana perombakan (to-be) yang mencakup fitur baru, perbaikan, dan optimasi — sebagai acuan pengembangan Aspira versi berikutnya.
1.1 Tujuan Dokumen
Mendokumentasikan fungsionalitas Aspira versi saat ini sebagai baseline.
Mengidentifikasi kelemahan teknis, keamanan, dan UX yang perlu diperbaiki.
Mendefinisikan kebutuhan fitur baru untuk perombakan (revamp) yang lebih baik, aman, dan skalabel.
Menjadi acuan bersama antara product owner, developer, dan stakeholder lain dalam pengembangan berikutnya.
2. Latar Belakang & Masalah
Berdasarkan penelusuran source code, Aspira dikembangkan secara bertahap (terlihat dari riwayat commit) mulai dari fitur dasar login dan form builder, hingga penambahan fitur analisis global otomatis dan redesain halaman login. Namun karena dibangun tanpa framework dan tanpa proses keamanan standar, terdapat sejumlah masalah mendasar yang berisiko besar apabila aplikasi ini digunakan secara produksi atau diakses dari luar jaringan lokal.
Masalah Utama yang Ditemukan
Keamanan kredensial: 
password admin disimpan dalam bentuk plain text di database dan dibandingkan langsung tanpa hashing (bcrypt/argon2).
Kredensial rahasia ter-hardcode: 
kredensial database dan App Password Gmail SMTP tertulis langsung di dalam kode api.php, bukan di file environment/konfigurasi terpisah.
Manajemen sesi lemah: 
status login hanya disimpan di sessionStorage browser (client-side), tanpa token/session terenkripsi di server, sehingga rentan dimanipulasi.
Tidak ada proteksi API: 
endpoint api.php membuka header 'Access-Control-Allow-Origin: *' dan tidak memvalidasi peran/izin pengguna di sisi server untuk aksi sensitif (mis. hapus form, hapus admin).
Rentan XSS: 
beberapa data ditampilkan ke email/HTML tanpa sanitasi penuh, serta tidak ada validasi input terhadap konten yang diunggah pengguna publik.
Tidak ada rate limiting/CAPTCHA: 
form publik dapat disubmit berulang kali tanpa batas, membuka peluang spam dan penyalahgunaan.
Error reporting aktif di production: 
display_errors diaktifkan secara permanen, berpotensi membocorkan detail struktur server ke pengguna.
Keterbatasan fungsional: 
tipe pertanyaan terbatas (teks, angka, textarea, radio, select, checkbox, rating), belum ada logika bercabang (conditional logic), validasi field custom, batas jumlah respons, atau jadwal buka/tutup form.
UX admin manual: 
tidak ada pagination pada daftar respons/formulir dalam jumlah besar, tidak ada pencarian/filter respons, dan ekspor hanya format .xls sederhana (HTML table).
Tidak ada draft/versioning: 
form yang sedang dibuat langsung tersimpan sebagai entitas final; tidak ada status draft/publish maupun riwayat perubahan.

3.3 Alur Utama Pengguna
Admin login → dashboard menampilkan daftar formulir & jumlah respons.
Admin membuat formulir baru via form builder, menambahkan field, opsional banner gambar, lalu menyimpan → sistem menghasilkan tautan publik unik.
Tautan dibagikan ke responden publik → responden mengisi form_public.html → data tersimpan ke tabel responses (JSON) → email konfirmasi ke responden & notifikasi ke admin dikirim via SMTP Gmail.
Admin melihat rekap di dashboard, analisis visual di analysis_report.html, atau mengekspor data ke Excel.
Admin (role tertentu) dapat menambah/menghapus akun admin lain di admin_management.html.

5. Visi & Tujuan Perombakan (Revamp)
Perombakan Aspira ditujukan untuk mengubahnya dari aplikasi form sederhana berbasis file PHP tunggal menjadi platform survei/feedback yang aman, terstruktur, dan siap digunakan secara lebih luas (multi-tim/multi-departemen), tanpa kehilangan kesederhanaan penggunaan yang sudah menjadi kekuatan Aspira saat ini.
Tujuan Utama
Menjadikan aplikasi aman untuk dipakai secara publik/production (keamanan data & kredensial).
Meningkatkan fleksibilitas form builder (tipe field lebih kaya, logika bercabang, validasi).
Memperkuat analisis data (insight otomatis, filter, perbandingan, export lebih lengkap).
Memperbaiki skalabilitas arsitektur (kode terstruktur, siap dikembangkan tim lebih besar).
Meningkatkan pengalaman pengguna admin maupun responden publik.

8. Rekomendasi Tumpukan Teknologi (Opsional)
Apabila perombakan dilakukan dari nol atau bertahap, berikut opsi arah teknis yang bisa dipertimbangkan — tetap dapat disesuaikan dengan kapasitas tim dan infrastruktur yang tersedia:
Backend: 
PHP dengan framework (Laravel) untuk mempertahankan familiaritas tim, atau Node.js (Express/NestJS) bila ingin satu bahasa dengan frontend.
Database: 
Tetap MySQL/MariaDB dengan penambahan indexing dan migrasi skema terstruktur (mis. menggunakan tool migration bawaan framework).
Frontend: 
Framework komponen modern (React/Vue) menggantikan HTML+JS manual per halaman, agar form builder lebih mudah dikembangkan (drag-and-drop yang lebih baik).
Autentikasi: 
Session berbasis server atau JWT dengan refresh token, ditambah opsi 2FA untuk admin.
Penyimpanan File: 
Object storage (S3-compatible) untuk banner/lampiran.
Email: 
Tetap gunakan PHPMailer atau migrasi ke layanan transaksional (mis. SendGrid/Mailgun) agar deliverability lebih terjamin dan tidak bergantung pada App Password Gmail pribadi.
